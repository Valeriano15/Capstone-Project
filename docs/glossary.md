# Glossary

Shared vocabulary for this project. If a term is used differently in general security practice,
the meaning here is what we use in our code and paper.

| Term | Meaning in this project |
| --- | --- |
| Assessment | A scoped process for evaluating selected security conditions |
| Penetration testing | Authorized testing that may validate whether selected weaknesses can be exploited |
| Discovery | Identifying reachable hosts, services, and observable details within scope |
| Candidate vulnerability | A possible issue suggested by evidence but not yet established |
| Validation | A defined procedure to gather stronger evidence about a candidate issue |
| Metasploit Framework | The testing framework integrated into the project |
| RPC | Remote procedure call, the interface the app uses to drive Metasploit |
| CVE | A standardized identifier for a publicly disclosed vulnerability |
| CVSS | A framework for communicating vulnerability severity |
| Ground truth | The independently established expected condition used to evaluate a result |
| False positive | Reporting a vulnerability that is not present for the defined case |
| False negative | Failing to identify a vulnerability known to be present for the defined case |
| Inconclusive | Evidence does not support a reliable positive or negative conclusion |
| MVP | Minimum viable project, the smallest complete version that supports the research question |
| Baseline | A defined comparison workflow |
| Provenance | The origin, version, and processing history of evidence or a claim |
| Prompt injection | Untrusted content attempting to alter an AI system's intended behavior |
| Human-in-the-loop | A person retains specified approval, review, or decision responsibilities |
| Reproducibility | Another person can repeat the documented procedure and inspect the results |
